# ざわモク

React / TypeScript / Vite の作業タイマー。開始ボタンから環境音を再生します。

## 開発

- `npm run dev`: 開発サーバー
- `npm run build`: 型チェックと本番ビルド
- `npm run lint`: 静的チェック
- `npm test`: 音声制御の自動テスト（Vitest）

自動テストはWeb Audioとブラウザイベントをモックし、中断・復帰、手動停止、自動再開の拒否、読み込み失敗、終了・再開始時の非同期処理の競合を検証します。実際の音の出力やOSからの割り込み通知は、以下の実機確認で検証します。

## 環境音と割り込み対応

`src/audio/AmbientAudio.ts` が既存の6音源をループ再生し、HRTF PannerNodeで周囲に配置します。マスター音量のフェードでは個別音量・音源位置・再生位置を変更しません。作業の一時停止で消音、再開で1秒かけてフェードインし、作業終了で音声グラフを破棄します。音声の中断だけでは作業タイマーを止めません。

AudioContextのstatechangeと、対応ブラウザではnavigator.audioSessionのstatechangeから中断を検知します。中断時にゲインをゼロにし、ブラウザがrunningに戻した際にフェードインします。中断終了後のsuspended、ページ再表示・フォーカス復帰では再開を試みます。手動停止中には自動復帰しません。リロード後はユーザー操作で音声を再開します。

Webでは着信・アラーム・通知音を直接識別できず、すべての通知で中断イベントが発生する保証はありません。OSが先に音声を止める場合、停止前のフェードアウトは保証できません。ページ非表示だけを理由に再生は止めません。自動再開が拒否・保留された場合は画面の「環境音を再生・再開」を使用します。音声のバックグラウンド継続や復帰動作はブラウザ・OS依存です。

## 実機確認項目

1. 開始操作で環境音が再生され、左右・奥行きが感じられる。
2. 着信（応答・拒否）、アラーム、Siri前後で音声の状態と復帰を確認する。通知音は中断が通知されるかも確認する。
3. 割り込み後に音量が急に最大にならず、1秒程度で戻る。復帰途中の再割り込みも確認する。
4. 中断中に作業を一時停止すると、割り込み終了後も音が出ない。手動再開で音が戻る。
5. タブ切り替え、画面ロック、Bluetooth接続変更後の挙動を確認する。Webにはイヤホン切断を確実に検知する共通APIがないため、スピーカーへの切替挙動も実機で確認する。
6. 自動復帰できない場合に再開ボタンが使える。リロード後もボタンで再生できる。
7. 音源の取得を失敗させると再試行が表示される。読み込み中の終了・再開始で二重再生しない。
8. 作業終了後に音が止まり、再開始時に重複しない。
